## 知识点

### 三步骨架

所有文件程序都是同一个形状：

```c
FILE *fp = fopen("文件名", "方式");   // ① 打开
// ... 读写 ...                        // ② 用
fclose(fp);                           // ③ 关闭
```

漏掉①，后面的函数没有卡可用；漏掉③，写进去的数据可能还在缓冲区里没落到磁盘。

### `fopen` 不读内容

`fopen` 那一刻**不会**把文件内容读进内存，它只做两件事：向操作系统登记“我要用这个文件”，然后在内存里分配一块缓冲区。真正的搬运发生在 `fgetc` / `fread` 这些函数里。

### `FILE *` 是“借书卡”，不是文件本身

`fp` 指向的是内存里的一块结构体，上面记着：对应哪个文件、现在读写到第几个字节、缓冲区在哪、有没有出错或到底。

文件本身一直在磁盘上，`fp` 从没碰过它。所以“打开”不等于“读进内存”。

`fgetc` 返回 `int` 而不是 `char`，就是为了能返回 `EOF`（-1）这个额外值；`char` 可能装不下它。

### `"w"` 会先清空文件

`"w"` 的完整含义是“我要写，从零开始”：**先把文件截断成 0 字节，再写**。原来的内容全部消失，没有备份。

本次实践里踩过这个坑：`dd.txt` 里先写了 `'s'`，改成 `'x'` 再跑一次，`s` 就没了。

想保留原内容往后加，要用 `"a"`（append）。

### 单引号与双引号不是一回事

| 写法 | 类型 | 内存里是什么 |
|---|---|---|
| `'r'` | `char` | 1 个字节 |
| `"r"` | 字符串 | 2 个字节（`r` 加结尾的 `'\0'`） |

`fopen` 第二个参数要的是**字符串**，写成 `'r'` 类型不对，编译器直接报错。`fputc` 第一个参数要的是**单个字符**，所以用单引号。

字符串靠末尾的 `'\0'` 才能知道读到哪儿结束，这就是函数需要“地址”而不是“字符值”的原因。

### `fopen` 失败返回 `NULL`

文件不存在、没权限、磁盘满，`fopen` 都会返回 `NULL`。这时后面拿 `NULL` 去 `fgetc` 会直接崩。

所以真实程序第一句永远是检查：

```c
FILE *fp = fopen("dd.txt", "r");
if (fp == NULL) {
    printf("Invalid value!");
    return 1;
}
```

**检查必须在使用之前**。原稿把 `if(fp == NULL)` 写在 `fgetc` 后面，等于没有检查。

### `fgets` 的三个参数

```c
fgets(buf, 100, fp);   // 存到哪 / 最多读多少 / 用哪张卡
```

- `100` 是 **`buf` 的容量上限**，不是“这行有多少字”。实际读到 `\n` 或读满 99 个字符就停（留 1 个给 `'\0'`）。
- 换行符 `'\n'` 会被**一起存进 `buf`**，之后再 `printf("%s\n", buf)` 就会多一个空行。
- 一行太长会被截断，剩下的留在文件里，下次 `fgets` 接着读。

### `fscanf` 用 `&` 送值，不用返回值

`fscanf` 的返回值是“**成功读到了几项**”，不是读到的值本身：

```c
fscanf(fp, "%d %f", &score1, &score2);   // 返回 2 表示两项都读到了
```

写 `int score1 = fscanf(fp, 100, "%d")` 有三处错：返回值不是分数、`100` 被当成了格式串、`"%d"` 缺了变量地址。

对比记忆：`fscanf` = `scanf` 前面多一个参数卡。

### 文本与二进制

| | 文件里存什么 | 100 个 float |
|---|---|---|
| 文本（`fprintf`） | 翻译成字符 `'9' '2' '.' '5'` … | 约 600~1000 字节，看数值长短 |
| 二进制（`fwrite`） | 内存原样的字节 | 正好 400 字节，永远不变 |

- 文本多一道“数值转字符串”的翻译，慢一些，还有精度风险（`%f` 默认只写 6 位小数）。
- 二进制不翻译，像一个复印机，精度无损，但文件大小和机器相关（字节序、`float` 到底几字节、结构体对齐），而且人看不懂。
- 取舍：数据只在程序之间传用二进制；要给人看、给 Excel 或别的软件读、长期存档，用文本。

文件本身不认类型，只有字节。是程序**约定**每 4 个字节切一刀、按 `float` 解释。

### `"b"` 不是 bit

`"wb"` / `"rb"` 里的 `b` 是 binary（二进制模式）。它管的是换行符转换：Windows 上文本模式会把每个 `\n` 偷偷变成 `\r\n`（2 个字节），读的时候再换回来。二进制模式不做这个转换，原样进出。

存二进制数据不加 `b`，文件大小会变，读回来的内容也会对不上。

### 读写要重新打开

`file_string_io.c` 里写完先 `fclose`，再重新 `fopen(..., "r")`，才能读到自己刚写的东西。因为数据可能还在缓冲区里没落到磁盘。

### 格式化只影响“写出去的样子”

`%.3f` 只改变写进文件或屏幕的文本，内存里的 `float` 值一点没变。所以 `fprintf(fp, "%.3f", x)` 写出的文件比 `%f` 短。

### 格式符必须和类型一致

`printf("%d", b[84])`（`b` 是 `float`）不会报错，但会把 4 个字节按整数解释，打出一个毫无意义的数。`float` 要用 `%f`。

反过来也一样：`fgetc` 返回的是 `int`，必须用 `int` 变量接、用 `%d` 打。写成 `float c; c = fgetc(fp); printf("%d", c);` 会打出 `-1.000000` 这种怪东西，因为 `%d` 在按整数解读一块实际装着浮点数的内存。

### 10.4 文件定位：`fseek` / `ftell` / `rewind`

```c
fseek(fp, 偏移量, 起点);   // 起点：SEEK_SET / SEEK_CUR / SEEK_END
long pos = ftell(fp);      // 现在的位置（离文件开头多少字节）
rewind(fp);                // 回到文件开头
```

- **偏移量的单位是字节，不是“第几个数据”**。要跳过 84 个 `float`，得写 `84 * sizeof(float)`（= 336），不是 84。写成 84 会读到 `a[21]`。
- 三个起点常量定义在 `stdio.h` 里（`SEEK_SET`=`0`，`SEEK_CUR`=`1`，`SEEK_END`=`2`），不用自己定义，也不能省略不写——`fseek` 没有默认值。
- `SEEK_END` 不是“移动到最后一个字节”，而是“**以文件末尾作为量距离的起点**”。

**求文件大小的标准三步**：

```c
fseek(fp, 0, SEEK_END);   // 把位置挪到末尾
long size = ftell(fp);    // 问坐标：400
rewind(fp);               // 一定要倒回开头，否则后面读不到东西
```

它一个字节都没读。原因：文件长度是元信息，操作系统本来就记着，所以“末尾在哪”不需要数。

位置坐标从 0 开始，所以 400 字节的文件，最后一个字节下标是 399，而“末尾”是位置 400。

**随机读 vs 顺序读**：`fread(a, sizeof(float), 100, fp)` 从头一口气读到底是顺序；`fseek` 之后只读 1 块是随机。随机读写可以跳过前面 84 个不读。

**`fread(&x, ...)` 里的 `&`**：`a` 是数组名，本身就是地址可以省略 `&`；`x` 是普通变量，必须写 `&x` 才能把字节送进去。

### 10.5 出错检测：读不到 ≠ 出错

| 现象 | `feof` 为真 | `ferror` 为真 |
|---|---|---|
| 正常读到文件末尾 | ✅ | ❌ |
| 读的时候真出错（磁盘坏块、拔掉 U 盘） | ❌ | ✅ |

`fgetc` 在两个情况下都返回 `EOF`（-1），只看返回值分不清是哪种，所以要再看这两盏灯。

- `feof` / `ferror` 都是**事后检查**，不能用来控制循环。标准只保证“非 0 = 真”，不保证恰好是 1（本机 `feof` 读到末尾后返回 16）。所以只用 `if (feof(fp))` 判断真假，别把数值当 1 来比。
- **不要写 `while (!feof(fp)) fgetc(fp);`**：`feof` 要等读完最后一个字节之后才变真，循环会多跑一次，处理到一个多余的数据。正确写法是看函数返回值：`while (fread(&x, sizeof(float), 1, fp) == 1) { ... }`。
- `clearerr(fp)` 把两盏灯都清掉。`rewind` 和 `fseek` **不会**清标志，这在“同一个文件用到末尾、倒回开头再用”时会出问题。
- 开文件失败（`fopen` 返回 `NULL`）要 `return 1` 直接退出，只打印不退出等于没检查——后面 `fseek(NULL, ...)` 会直接崩。
